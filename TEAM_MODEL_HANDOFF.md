# Required team-authored models — manual handoff

The generated humanoids, weapons and level primitives are **development placeholders**. They do not establish that the team created models in Blender or Maya. No team-authored `.blend`, `.ma`, `.mb` or exported model was supplied to this project.

## Model 1: original zombie character

1. In Blender or Maya, work in metres; model a roughly 1.9 m humanoid with recognisable head, torso, arms, hands, legs and feet. Add original silhouette details, torn clothing and facial features. Keep a sensible real-time polygon budget.
2. Name objects and bones clearly. UV unwrap and assign the team's materials. Create a Humanoid-compatible armature in a T or A pose, bind/weight the mesh, and test shoulders, elbows, knees and hips.
3. Keep the native authoring file, work-in-progress screenshots and named team ownership in `Assets/Models/Team/Zombie/Source/`. Store large source files with Git LFS if the team enables it.
4. Export FBX with mesh and armature, applied transforms, unit scale, no extra leaf bones. Put the export under `Assets/Models/Team/Zombie/`. In Unity set Rig > Animation Type = Humanoid, Avatar Definition = Create From This Model, then Configure and verify the mapping.
5. Make a visual-only prefab with Animator, no NavMeshAgent, Rigidbody or duplicate health/brain. Set Apply Root Motion off. Assign `Assets/Animations/Enemies/Enemy.controller` to its Animator.
6. Open `Assets/Prefabs/Enemies/EnemyBase.prefab` in Prefab Mode. Replace its Visual child, keep the root shared components and capsule, and assign the new Animator to EnemyAnimationController. Retain scale and foot origin. Check the four variants inherit the visual replacement; their material tint overrides may need resetting on the new renderers.
7. Verify every locomotion/attack/hit/death state in Play Mode. For Elite, use the larger variant scale/collider or provide a separate original Elite visual.

## Model 2: original defensive barricade

1. Create an original 2.4 m wide, 1.3 m tall, 0.55 m deep barricade using uneven timber, braces, bolts or sheet metal. Model in metres with the pivot at its centre and apply transforms.
2. UV unwrap and texture it. Create one intact model and, optionally, a small set of broken pieces. Use simple box collision proxies; avoid dynamic non-convex MeshColliders.
3. Keep native source, WIP screenshots, exported FBX and textures in `Assets/Models/Team/Barricade/` with clear author attribution.
4. In ZombieMap, replace only the renderer/mesh of the Barricades children. Retain the existing Rigidbody, simple collider, NavMeshModifier, NavMeshObstacle and DestructibleBarricade components. Set root scale to one and adjust collider/obstacle dimensions to the new real-world size.
5. Optionally assign a debris prefab to DestructibleBarricade. Debris pieces may have lightweight Rigidbodies and simple colliders; add a finite cleanup time. Test that destruction frees the navigation route.

## Unity import and validation workflow

The project creates an empty catalog at `Assets/Data/TeamArtCatalog.asset` and these drop folders under `Assets/Models/Team/` when Phase 18 setup runs. No model is generated by this workflow. Keep the source files and evidence associated with the actual team author.

1. Import the authored FBX files and create visual-only prefabs. Keep root transforms at scale 1. The zombie prefab must have a valid Humanoid Avatar, a skinned mesh with materials, and no duplicate movement or root physics. Assign the shared `Assets/Animations/Enemies/Enemy.controller`.
2. The barricade prefab must have a Renderer and no colliders, Rigidbody or NavMesh components. The existing gameplay barricade retains those components. Optional debris can be assigned separately.
3. Assign the prefabs in `Assets/Data/TeamArtCatalog.asset`; record the actual author/team and source project path. Mark `modelsAuthoredByTeam` only when that statement is accurate.
4. Run **Zombie Outbreak > Team Art > Validate supplied models**. Resolve each reported issue before applying.
5. Run **Zombie Outbreak > Team Art > Apply validated models to game**. It replaces the EnemyBase Visual child and barricade renderers, keeps shared gameplay components, then rebakes and validates navigation. Review scale, materials, variant tints, hit alignment and the four enemy animations in Play Mode.

If the catalog fields are empty, the existing greybox remains unchanged. Unity cannot verify who authored a model; retain native Blender/Maya files, work-in-progress evidence and accurate contribution records.
